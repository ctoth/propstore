# Time, Clocks, and the Ordering of Events in a Distributed System

## One-Sentence Summary
Defines the "happened before" relation (->) as the smallest irreflexive partial order generated by process order and message send/receive, gives implementation rules IR1/IR2 for logical clocks that satisfy the Clock Condition (a -> b implies C<a> < C<b>), extends it to a total order (=>) by tie-breaking on process order, uses that total order for a fully distributed mutual-exclusion / replicated-state-machine algorithm, and specializes the rules (IR1'/IR2') to physical clocks with a proven synchronization bound epsilon ~ d(2*kappa*tau + xi). *(pp.558-564)*

## Problem Addressed
In a distributed system, "it is sometimes impossible to say that one of two events occurred first"; the order of events is only partial, and problems arise when designers assume a total temporal order. The paper defines ordering in terms of events observable within the system rather than physical time, and gives algorithms for totally ordering events and synchronizing clocks. *(p.558)*

## Key Contributions
- Formal definition of the "happened before" relation -> and of concurrency (a -/-> b and b -/-> a) *(p.559)*
- Space-time diagram interpretation: a -> b iff one can go from a to b moving forward in time along process and message lines; a -> b means a can causally affect b *(p.559)*
- Logical clocks and the Clock Condition, with sufficient conditions C1, C2 and implementation rules IR1, IR2 *(p.560)*
- Total ordering => extending ->, by clock value with an arbitrary process ordering as tie-breaker *(p.561)*
- Distributed mutual-exclusion algorithm (five rules) satisfying conditions I-III without a central scheduler *(p.561-562)*
- Generalization: replicated State Machine synchronization, each process simulating the machine over commands ordered by => *(p.562)*
- Identification of "anomalous behavior" caused by causality external to the system, and the Strong Clock Condition *(p.562)*
- Physical-clock conditions PC1, PC2; rules IR1', IR2'; Theorem bounding clock skew, proved in the Appendix *(pp.563-565)*

## Methodology
Purely formal/analytical. Systems are modeled as collections of processes, each a sequence of events with an a priori total order; sending and receiving messages are events. Ordering is defined via a minimal relation closed under three rules. Logical clocks are functions from events to numbers; correctness is defined only in terms of event order. Physical clocks are modeled as continuous, differentiable functions of Newtonian physical time t except at reset jumps. The theorem is proved by bounding clock lag along paths in a strongly connected communication graph. *(pp.558-564)*

## Definitions

**System model.** A distributed system is a collection of distinct, spatially separated processes communicating by exchanging messages; a system is distributed "if the message transmission delay is not negligible compared to the time between events in a single process." *(p.558)* A single process is defined to be a set of events with an a priori total ordering. *(p.559)* Footnote 1: the choice of what constitutes an event affects the ordering of events in a process (e.g., receipt of a message may denote setting an interrupt bit or executing the interrupt handler). *(p.559)* Footnote 2: messages may be received out of order; sending several messages may be a single event, but receipt of a single message is assumed not to coincide with sending or receipt of any other message. *(p.559)*

**Definition (happened before).** The relation -> on the set of events of a system is the smallest relation satisfying: (1) if a and b are events in the same process and a comes before b, then a -> b; (2) if a is the sending of a message by one process and b is the receipt of the same message by another process, then a -> b; (3) if a -> b and b -> c then a -> c. Two distinct events a and b are *concurrent* if a -/-> b and b -/-> a. *(p.559)*

**Irreflexivity assumption.** a -/-> a for any event a ("Systems in which an event can happen before itself do not seem to be physically meaningful"), which makes -> an irreflexive partial ordering on all events. *(p.559)*

**Relativity remark.** In relativity, ordering is defined in terms of messages that *could* be sent; this paper only considers messages that actually *are* sent, so correctness can be judged from events that *did* occur. *(p.559)*

**Logical clock.** A clock C_i for each process P_i is a function assigning a number C_i<a> to any event a in that process; the system clock C assigns C<b> = C_j<b> if b is in P_j. No assumption about relation to physical time; may be implemented by counters. *(p.559)*

**Clock Condition.** For any events a, b: if a -> b then C<a> < C<b>. The converse cannot be expected, since it would force concurrent events to occur at the same time (in Fig. 1, p2 and p3 are both concurrent with q3, but p2 -> p3). *(p.560)*

**C1.** If a and b are events in process P_i and a comes before b, then C_i<a> < C_i<b>. *(p.560)*

**C2.** If a is the sending of a message by process P_i and b is the receipt of that message by process P_j, then C_i<a> < C_j<b>. *(p.560)*

C1 and C2 together imply the Clock Condition. In the space-time diagram, C1 means there is a tick line between any two events on a process line; C2 means every message line crosses a tick line. *(p.560)*

**Tick lines.** Clock ticks occur between a process's events (if C_i<a>=4 and C_i<b>=7 for consecutive events, ticks 5, 6, 7 occur between them); dashed tick lines join like-numbered ticks. Tick lines can be viewed as time coordinate lines of a Cartesian coordinate system on space-time; Fig. 3 straightens them. Without physical clocks there is no way to decide which picture is better. *(p.560)*

**Total ordering =>.** If a is in P_i and b is in P_j, then a => b iff either (i) C_i<a> < C_j<b> or (ii) C_i<a> = C_j<b> and P_i < P_j, where < is an arbitrary total ordering of processes. The Clock Condition implies a -> b => a => b. *(p.561)*

**Strong Clock Condition.** Let script-S be the set of system events and underlined-S a set containing script-S together with all other relevant external events; let a bold arrow denote the happened-before relation for that larger set. For any events a, b in script-S: if a (bold ->) b then C<a> < C<b>. Not in general satisfied by logical clocks. *(p.562)*

**Physical clock.** C_i(t) is the reading of clock C_i at physical time t, assumed continuous and differentiable except at isolated jump discontinuities (resets). dC_i(t)/dt is its rate. A discrete clock is a continuous one with reading error up to 1/2 tick. Newtonian space-time is assumed (footnote 8). *(pp.562-563)*

**Message delays.** For a message m sent at physical time t and received at t': total delay nu_m = t' - t; the receiver knows a minimum delay mu_m >= 0 with mu_m <= nu_m; unpredictable delay xi_m = nu_m - mu_m. *(p.563)*

**Communication graph.** Directed graph with an arc P_i -> P_j for a direct communication line. A message is sent over an arc every tau seconds if for any t, P_i sends at least one message to P_j between t and t + tau. The diameter d is the smallest number such that for any distinct P_j, P_k there is a path from P_j to P_k of at most d arcs. *(p.563)*

## Key Equations

$$
C_i\langle a\rangle < C_j\langle b\rangle \text{ whenever } a \rightarrow b
$$
Where: the Clock Condition; C maps events to numbers. *(p.560)*

$$
a \Rightarrow b \iff C_i\langle a\rangle < C_j\langle b\rangle \;\lor\; (C_i\langle a\rangle = C_j\langle b\rangle \land P_i \prec P_j)
$$
Where: a in P_i, b in P_j, precedes is an arbitrary total order on processes. *(p.561)*

$$
\left| \frac{dC_i(t)}{dt} - 1 \right| < \kappa
$$
Where: PC1, for all i; kappa << 1 is a constant; for typical crystal-controlled clocks kappa <= 10^-6. *(p.563)*

$$
\left| C_i(t) - C_j(t) \right| < \epsilon
$$
Where: PC2, for all i, j; epsilon is a sufficiently small constant (variation in height of a tick line). *(p.563)*

$$
\frac{\epsilon}{1-\kappa} \le \mu
$$
Where: mu is less than the shortest interprocess transmission time (can be chosen as shortest distance between processes divided by speed of light, but may be much larger depending on transmission). This inequality together with PC1 and PC2 implies C_i(t + mu) - C_j(t) > 0, so anomalous behavior is impossible. Uses PC1: C_i(t + mu) - C_i(t) > (1 - kappa) mu, and the assumption that clocks are only ever set forward. *(p.563)*

$$
C_j(t') = \max\left(C_j(t'-0),\; T_m + \mu_m\right)
$$
Where: IR2'(b), on receipt of m at time t'; C_j(t' - 0) = lim_{delta->0} C_j(t' - |delta|) (footnote 9). *(p.563)*

$$
\epsilon \approx d\,(2\kappa\tau + \xi)
$$
Where: Theorem bound on synchronization, holding for all t >~ t_0 + tau d, approximations assume mu + xi << tau. *(p.563)*

### Appendix proof equations *(pp.564-565)*

$$
C_i^{t}(t') = C_i(t) + \int_t^{t'} \left[ \frac{dC_i(t)}{dt} \right] dt
$$
Where: (1) C_i^t is a clock set equal to C_i at time t, running at C_i's rate, never reset; for all t' >= t. *(p.564)*

$$
C_i(t') \ge C_i^{t}(t')
$$
Where: (2), for all t' >= t. *(p.564)*

$$
C_2^{t_2}(t) \ge C_1(t_1) + (1-\kappa)(t - t_1) - \xi
$$
Where: (3), P_1 sends at t_1 to P_2, received at t_2 with unpredictable delay <= xi, t_0 <= t_1 <= t_2, for all t >= t_2. Derived via (1)+PC1, then IR2'(b): C_2^{t_2}(t) >= C_1(t_1) + mu_m + (1-kappa)(t - t_2) = C_1(t_1) + (1-kappa)(t - t_1) - [(t_2 - t_1) - mu_m] + kappa(t_2 - t_1) >= C_1(t_1) + (1-kappa)(t-t_1) - xi. *(p.564)*

$$
C_{n+1}^{t_{n+1}}(t) \ge C_1(t_1') + (1-\kappa)(t - t_1') - n\xi
$$
Where: (4), chain of n hops with t_i <= t_i' < t_{i+1}, t_0 <= t_1, P_i sending at t_i' to P_{i+1} received at t_{i+1} with unpredictable delay < xi; for t >= t_{n+1}. From PC1, IR1', IR2': C_1(t_1') >= C_1(t_1) + (1-kappa)(t_1' - t_1). *(p.564)*

$$
C_{n+1}(t) \ge C_1(t_1) + (1-\kappa)(t - t_1) - n\xi
$$
Where: (5), for t >= t_{n+1}. *(p.564)*

$$
C_i(t) \ge C_j(t_1) + (1-\kappa)(t - t_1) - d\xi
$$
Where: (6), for any i, j and t, t_1 with t_1 >= t_0 and t >= t_1 + d(tau + nu), where nu = mu + xi; uses a path P = P_0, ..., P_{n+1} = P', n <= d, with t_i' - t_i <= tau and t_{i+1} - t_i' <= nu. *(p.564)*

$$
C_i(t) \le C_x(t_x) + (1+\kappa)(t - t_x)
$$
Where: (7), C_x is the clock with the largest value at t_x >= t_0 + mu/(1-kappa); all clocks run at rate < 1+kappa; for all i and t >= t_x. A message m is treated as having a clock C_m running at constant rate with C_m(t) = t_m, C_m(t') = t_m + mu_m, so dC_m/dt <= 1; IR2'(b) sets C_j(t') = max(C_j(t'-0), C_m(t')), so clocks are reset only by setting them equal to other clocks. *(p.564)*

$$
C_i(t) \le C_q(t_x) + (1+\kappa)(t - t_x)
$$
Where: (8i), case C_x is clock C_q of process P_q. *(p.564)*

$$
C_i(t) \le C_q(t_1) + (1+\kappa)(t - t_1)
$$
Where: (8ii), case C_x is the clock C_m of a message sent at t_1 by P_q; uses C_x(t_x) <= C_q(t_1) + (t_x - t_1). Chain: C_q(t_x - mu/(1-kappa)) <= C_q(t_x) - mu [PC1] <= C_m(t_x) - mu [choice of m] <= C_m(t_x) - (t_x - t_1) mu_m / nu_m [mu_m <= mu, t_x - t_1 <= nu_m] = T_m [def of C_m] = C_q(t_1) [IR2'(a)]; hence t_x - t_1 <= mu/(1-kappa) and t_1 >= t_0. *(p.564)*

$$
C_i(t) \le C_q(t_1) + (1+\kappa)(t - t_1)
$$
Where: (9), combining (8i) (with t_1 = t_x) and (8ii): for any t, t_x with t >= t_x >= t_0 + mu/(1-kappa) there is a P_q and t_1 with t_x - mu/(1-kappa) <= t_1 <= t_x such that this holds for all i. *(p.565)*

$$
C_q(t_1) + (1-\kappa)(t - t_1) - d\xi \le C_i(t) \le C_q(t_1) + (1+\kappa)(t - t_1)
$$
Where: (10), for t >= t_x + d(tau + nu), combining (6) and (9). Setting t = t_x + d(tau + nu): d(tau+nu) <= t - t_1 <= d(tau+nu) + mu/(1-kappa). *(p.565)*

$$
C_q(t_1) + (t - t_1) - \kappa d(\tau+\nu) - d\xi \le C_i(t) \le C_q(t_1) + (t-t_1) + \kappa\left[d(\tau+\nu) + \frac{\mu}{1-\kappa}\right]
$$
Where: (11); gives an exact upper bound on |C_i(t) - C_j(t)| when mu + xi << tau does not hold. *(p.565)*

$$
C_q(t_1) + (t - t_1) - d(\kappa\tau + \xi) \lesssim C_i(t) \lesssim C_q(t_1) + (t - t_1) + d\kappa\tau
$$
Where: (12), approximate form using kappa << 1 and mu <= nu << tau. Hence |C_i(t) - C_j(t)| <~ d(2 kappa tau + xi) for all t >~ t_0 + d tau. *(p.565)*

## Algorithms

### Logical clock implementation rules *(p.560)*
- **IR1.** Each process P_i increments C_i between any two successive events. (Ensures C1.)
- **IR2.** (a) If event a is the sending of message m by P_i, then m contains timestamp T_m = C_i<a>. (b) Upon receiving m, P_j sets C_j greater than or equal to its present value and greater than T_m. (Ensures C2.) The receipt event is considered to occur after the setting of C_j ("just a notational nuisance").
- Changing C_i between events does not itself constitute an event. *(p.560)*

### Distributed mutual exclusion *(pp.561-562)*
Requirements: (I) a process granted the resource must release it before it can be granted to another; (II) different requests must be granted in the order in which they are made; (III) if every process granted the resource eventually releases it, every request is eventually granted. Resource initially granted to exactly one process. *(p.561)*

Assumptions (not essential; avoidable by message numbers and acknowledgment protocols): messages from P_i to P_j are received in the order sent; every message is eventually received; every process can send directly to every other. Each process keeps a private request queue initially containing T_0:P_0 requests resource, where P_0 is initially granted and T_0 is less than the initial value of any clock. Each rule's actions form a single event. *(p.561)*

1. To request the resource, P_i sends T_m:P_i requests resource to every other process and puts it on its own request queue.
2. When P_j receives T_m:P_i requests resource, it places it on its request queue and sends a timestamped acknowledgment to P_i. (Footnote 5: not needed if P_j already sent P_i a message timestamped later than T_m.)
3. To release, P_i removes any T_m:P_i requests resource message from its queue and sends timestamped P_i releases resource to every other process.
4. When P_j receives P_i releases resource, it removes any T_m:P_i requests resource from its queue.
5. P_i is granted the resource when (i) there is a T_m:P_i requests resource message in its queue ordered before any other request by => (a message is identified with its sending event), and (ii) P_i has received a message from every other process timestamped later than T_m. (Footnote 6: if P_i < P_j, P_i need only have received a message timestamped >= T_m from P_j.) Both conditions are tested locally. *(p.561)*

Correctness sketch: rule 5(ii) with FIFO delivery guarantees P_i has learned of all requests preceding its own; rules 3 and 4 are the only deletions, so condition I holds; II follows because => extends ->; rule 2 guarantees 5(ii) eventually holds; rules 3 and 4 give eventual 5(i), proving III. *(p.562)*

### Replicated State Machine *(p.562)*
A State Machine is a set C of commands, a set S of states, and a function e: C x S -> S; e(C, S) = S' means executing C in state S yields S'. For mutual exclusion, commands are P_i requests/releases resource; state is a queue of waiting requests with the head being granted. Each process independently simulates the machine using commands from all processes ordered by =>. A process can execute a command timestamped T when it has learned of all commands from all other processes with timestamps <= T. Footnote 7: if a process does not strictly alternate request and release, a release may delete zero, one, or more requests. *(p.562)*

### Physical clock rules *(p.563)*
- **IR1'.** For each i, if P_i does not receive a message at physical time t, then C_i is differentiable at t and dC_i(t)/dt > 0.
- **IR2'.** (a) If P_i sends m at physical time t, m contains timestamp T_m = C_i(t). (b) Upon receiving m at time t', P_j sets C_j(t') equal to max(C_j(t' - 0), T_m + mu_m).
- A process needs only its own clock and received timestamps. These are specializations of IR1 and IR2, so they satisfy the Clock Condition. Implementation concern: discrete ticks must be frequent enough to maintain C1. Clocks are always set forward, never back (setting back could violate C1). *(p.563)*

### Theorem *(p.563)*
Assume a strongly connected graph of processes with diameter d that always obeys IR1' and IR2'. Assume for any message m, mu_m <= mu for some constant mu, and for all t >= t_0: (a) PC1 holds; (b) there are constants tau and xi such that every tau seconds a message with unpredictable delay less than xi is sent over every arc. Then PC2 is satisfied with epsilon ~ d(2 kappa tau + xi) for all t >~ t_0 + tau d, where the approximations assume mu + xi << tau. Proof in Appendix. The author believes the theorem to be a new result because the requirement that clocks are never set backwards distinguishes this setting from prior work. *(pp.563-564)*

### Fast (re)initialization *(p.565)*
Each process sends a message which is relayed to every other process; can be initiated by any process; requires less than 2d(mu + xi) seconds assuming each message has unpredictable delay less than xi.

## Results Summary
- -> is an irreflexive partial order; concurrency is mutual non-reachability. *(p.559)*
- IR1 + IR2 guarantee a correct system of logical clocks (Clock Condition). *(p.560)*
- => is a total order extending ->; it depends on the clock system and is not unique; for any total order extending -> there is a clock system yielding it; only -> is uniquely determined by the system of events. *(p.561)*
- Fully distributed mutual exclusion satisfying I-III, with no central synchronizing process or storage. *(p.562)*
- Physical clocks obeying IR1'/IR2' with the theorem's hypotheses keep skew within ~ d(2 kappa tau + xi), eliminating anomalous behavior when epsilon/(1-kappa) <= mu. *(pp.563, 565)*

## Limitations
- The state machine approach requires active participation of all processes; failure of a single process halts the system. Failure is "beyond the scope of this paper"; a fault-tolerant method is referenced as [3]. *(p.562)*
- "the entire concept of failure is only meaningful in the context of physical time": without physical time a failed process cannot be distinguished from a pausing one. *(p.562)*
- FIFO and reliable delivery assumptions for mutual exclusion (avoidable by message numbers and acknowledgments). *(p.561)*
- "Eventually" is not made precise (footnote 4). *(p.561)*
- => is "somewhat arbitrary" and can disagree with user-perceived order (anomalous behavior). *(p.562, p.564)*
- The theorem's closed form is an approximation requiring mu + xi << tau; relation (11) gives the exact bound otherwise. *(p.565)*
- Newtonian space-time assumed; relativistic or gravitational effects require transforming proper time (footnote 8). *(p.562)*

## Arguments Against Prior Work
- A central scheduling process granting requests in order received does not satisfy condition II without extra assumptions: P1 requests from P0, then messages P2, which then requests from P0; P2's request may reach P0 first. *(p.561)*
- Physical-time-based definitions of "happened before" are unsuitable for specifications, which must be stated in terms of events observable within the system; real clocks are not perfectly accurate. *(p.558)*
- Prior clock-synchronization literature (ref [4]) is useful for estimating mu_m and adjusting rates, but the requirement that clocks are never set backwards distinguishes this setting. *(pp.563-564)*

## Design Rationale
- Define ordering using only messages actually sent, not messages that could be sent (contrast with relativity), so correctness is decidable from events that did occur. *(p.559)*
- Clocks are abstract counters with no timing mechanism; correctness is defined by event order, not physical time. *(p.559-560)*
- Arbitrary process priority < for tie-breaking; footnote 3 offers a "fairer" variant: if C_i<a> = C_j<b> and j < i, let a => b if j < C_i<a> mod N <= i, and b => a otherwise, with N the number of processes. *(p.561)*
- Two ways to avoid anomalous behavior: (1) have users carry timestamps explicitly (person issuing B asks for a timestamp later than T_A); (2) clocks satisfying the Strong Clock Condition, which physical clocks can do. *(p.562)*
- Physical clocks never set backward, to preserve C1. *(p.563)*

## Testable Properties
- -> is irreflexive and transitive; for events in the same process it agrees with process order. *(p.559)*
- Under IR1 and IR2, for every message, receiver clock after receipt > T_m; within a process, clock values strictly increase across events. *(p.560)*
- a -> b implies a => b; => is a strict total order. *(p.561)*
- The converse of the Clock Condition does not hold in general (concurrent events may have different clock values). *(p.560)*
- In mutual exclusion, at most one process satisfies rule 5 at any time, and grants follow => order of requests. *(p.562)*
- With PC1, PC2 and epsilon/(1-kappa) <= mu, C_i(t + mu) - C_j(t) > 0 for all i, j, t. *(p.563)*
- Under the theorem's hypotheses, |C_i(t) - C_j(t)| <~ d(2 kappa tau + xi) for t >~ t_0 + d tau. *(p.565)*
- Resynchronization via relayed broadcast completes in < 2d(mu + xi). *(p.565)*

## Relevance to Project
The happened-before partial order is a canonical non-commitment structure: it refuses to impose a total order where the evidence (actual messages) does not support one, and treats any total order as one of many admissible extensions chosen by policy (tie-breaking). This matches propstore's discipline of keeping orderings partial in storage and choosing a linearization only at render time. Relevant to provenance and federation (ordering of source imports and commits across repositories), to supersession stories (recency resolution needs a causally consistent order, not wall-clock time), and as contrast to Allen-style interval relations over TIMEPOINT values.
